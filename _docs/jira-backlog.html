Epic 1

Onboarding & Profile

First-launch flow that captures the player's identity (name, look), drops them into the World List with a personal greeting, and exposes a reachable Profile sheet for later edits.

RAI-101

Player can complete the welcome flow on first launch

As a new user, I want a brief intro screen and a single form step so that I can start a date without paperwork.

Size: MStatus: Done

Acceptance Criteria

  • Intro screen autoplays a muted ambient video and shows a "Start" CTA.
  • Form asks for: name (required, 2–30 chars), gender (3-way), preference.
  • Validation: empty/over-length name disables Start.
  • Tapping Start triggers the loading screen, then the casting picker.
  • Onboarding state persists in localStorage; relaunch goes straight to World List.

Definition of Done

  • Works on iOS Safari + Chrome (desktop & mobile).
  • Form gracefully restores last entered values if user backs out.
  • Manual QA on a fresh-cache profile completes the flow under 60 s.

UI Reference

Body class chain: flow-intro → flow-form → flow-loading → flow-survey → flow-final → flow-worlds. Driven by setFlow() in dialog.html.
RAI-102

Profile sheet for name / look edits + memory carousel

As a player, I want a profile drawer so I can edit my identity and re-read memory snapshots from past dates.

Size: MStatus: Done

Acceptance Criteria

  • Profile icon in World List top-right opens a full-height sheet.
  • Sheet shows: avatar, name, "Castings" tab (episodes the player was cast in by friends), and a memory carousel from past episodes.
  • Memory cards swipeable horizontally; each shows scene image + caption + meta.
  • Closing the sheet returns to World List with state intact (no reload).

Definition of Done

  • Memory list comes from PROFILE_MEMORIES data structure (wired to real save data in a later epic).
  • Castings list shows 6 items with role labels.
  • No layout shift when sheet opens/closes; transitions ≤ 350 ms.

UI Reference

Container #profileSheet; trigger button #wlOpenProfile; data source PROFILE_MEMORIES + MY_CASTINGS.

Dialog Engine v2 — bracket directive stack

Declarative scene composition layer that lets writers stack background, effect, transition, and UI hints per beat instead of toggling DOM by hand.

RAI-401

Bracket directives: [bg:...] [ui:...] [fx:...] [tr:...]

As a writer, I want to declare visual state on its own line so the engine can transition between scenes cleanly.

Size: LStatus: Done

Acceptance Criteria

  • Parser recognises lines made only of bracket directives and emits a single state-update event.
  • Each layer (bg / fx / tr / ui) is independently updatable; subsequent beats inherit the stack.
  • Supported values: bg:cutscene=foo.jpg, bg:scene=foo.jpg, bg:explore, bg:none; ui:cast-large, ui:cast-small, ui:inner-large, ui:inner-small, ui:narrative, ui:bubble, ui:multi, ui:write.
  • fx + tr presets are loaded from _config/fx-presets.json + _config/tr-presets.json at boot.

Definition of Done

  • Engine console logs [dialog-v2] fx presets loaded: (N) on boot.
  • Switching bg from cutscene → scene clears the previous layer to avoid mode confusion.
  • Documented in _docs/dialog-architecture.md.

UI Reference

[bg:cutscene=joy-street01.jpg] [tr:softCrossfade] [ui:narrative]
Narrative: Footsteps catch up beside you.
[ui:cast-large]
Joy: Hey, stranger.

Epic 8

AI Dialog Blocks (Generic)

Any dialog section the writer marks with (AI:id) ... (EndAI) can be transparently rewritten by GPT at render time, with the hand-written placeholder as a fallback.

RAI-801

(AI:id) ... (EndAI) block syntax + worker endpoint

As a writer, I want to wrap any dialog block in an AI marker so it gets fresh phrasing per playthrough but stays playable if AI fails.

Size: LStatus: Done

Acceptance Criteria

  • Parser collects lines between marker pair as the placeholder array.
  • Worker /ai-dialog endpoint receives id, attrs, placeholder, context; returns rewritten lines.
  • Engine eager-prefetches all AI blocks on script load (max 3 concurrent).
  • When the renderer reaches the block: if cache ready → splice in AI lines; else → use placeholder. Never deadlocks.
  • Stale cache (e.g. gift picked after prefetch) auto-refetches with the now-known gift context.

Definition of Done

  • 20 s wait timeout with soft loader on first hit; falls back to placeholder if AI doesn't return.
  • Worker enforces strict speaker palette (placeholder speakers only).
  • Body context includes player_name, scene, gift name + description.

UI Reference

(AI:vinyl-look mood=nostalgic length=8)
Mike: A record on the deck. Indie folk.
Eros: I should have guessed.
(EndAI)
RAI-802

AI returns mixed-cast lines → auto UI mode per speaker

As an engine, when AI returns lines from different speaker tiers (narrative + inner + cast), I want the UI mode to switch per-tier so the layout doesn't pile up.

Size: SStatus: Done

Acceptance Criteria

  • Speaker tier → UI: narrative → ui:narrative; inner voices → ui:inner-small; cast (boy/girl/joy/dog) → ui:cast-large.
  • Auto state-update events inserted between speaker-tier changes.
